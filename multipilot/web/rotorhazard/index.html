Eight RotorHazard nodes from one ESP32-C5

C5MK is free firmware that turns an ESP32-C5 into a multi-pilot 5.8 GHz receiver. Plug it into the computer running RotorHazard over USB and RH sees eight standard timer nodes, so there's no stack of RX5808 modules, node board, ESP32-S3 or plugin.

Set it up

  1. Flash the firmware. Use the C5 flasher and choose Multi Pilot for your board. C5MK 1.2.0 or later is needed; use the latest release.
  2. Plug it in. Connect the C5's USB port to the RotorHazard computer with a data cable, and fit a 5.8 GHz antenna.
  3. Add the port. In RotorHazard, open Advanced Settings > Hardware > Serial Ports, add the C5's port (COM5 on Windows, /dev/ttyACM0 or a /dev/serial/by-id/ path on Linux) and restart RH.
  4. Tune. RH finds eight nodes and applies its frequency profile. Assign pilots to seats and calibrate EnterAt and ExitAt in Sensor Tuning. The readings differ from an RX5808's, so calibrate rather than reusing old thresholds.
  5. Race. The C5 detects each gate crossing and RotorHazard records, announces and saves the laps as usual.

Questions

Which ESP32-C5 boards work with RotorHazard?

Direct USB to RotorHazard is verified on the Waveshare ESP32-C5-Zero. The Seeed Studio XIAO ESP32-C5 runs the same firmware and is tested with FPVGate; its USB connection to RotorHazard is still to be validated.

Do I need a plugin or special RotorHazard version?

No. The C5 speaks RotorHazard's standard serial node protocol (node API 36), so a normal RotorHazard install picks it up once the serial port is added.

Has it been raced with a full field?

Not yet. Eight-node discovery and live RSSI are verified, and timing works in local RotorHazard testing. Races with two or more real pilots, and lap accuracy against video, are still to be measured.

Can I use the same receiver without RotorHazard?

Yes. The same firmware runs the browser lap timer for 1–4 pilots, the live signal dashboard and the VTX check. Only one program can use the USB port at a time, so close RotorHazard first.
